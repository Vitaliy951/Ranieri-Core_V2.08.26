## 2. Ключевые разработанные ИТ-продукты холдинга

### 2.1. Программный комплекс B2B SaaS-скоринга и автооценки «Ranieri Core»

Собственный программный продукт (SaaS/API платформа) для автоматизации процессов андеррайтинга, оценки кредитных рисков физических лиц и предиктивного анализа стоимости залогов недвижимости в режиме реального времени.

- **Класс ПО (согласно Классификатору Минцифры РФ):** `04.14 Средства интеллектуального анализа данных (Data Mining)` / `04.07 Средства управления базами данных`.
- **Технологический стек:** Python (FastAPI), PyTorch (SOTA-архитектура Long Short-Term Transformer — LSTR), LightGBM/CatBoost, СУБД ClickHouse, PostgreSQL, Docker, Kubernetes.
- **Функциональные возможности:**
  - Асинхронное обогащение данных и автоматический сбор верифицированных векторов признаков через шлюзы СМЭВ 3.0 (ФНС, ФССП, СФР) и коммерческие B2B API-интерфейсы.
  - Расчет индивидуального кредитного балла и калибровка индивидуальной вероятности дефолта заемщика ($PD_{12M}$) без участия человека (STP-процесс).
  - Нейросетевой пространственно-временной анализ 10-летнего Big Data архива объявлений недвижимости для вычисления справедливой рыночной цены (Fair Value) и моделирования Stress LTV залога на 3 года вперед.
  - Интегрированный модуль **Explainable AI** — автоматическая генерация структурированного дерева логических рассуждений ИИ (`ai_reasoning_tree`) для обеспечения прозрачности и комплаенса алгоритмов перед регуляторами.

### 2.2. ИИ-модуль автоматического скоринга и подбора государственных контрактов «Tender_Scoring_Engine»

Внутренний программный комплекс автоматизации бизнес-процессов B2G-направления деятельности компании.

- **Класс ПО:** `04.14 Средства интеллектуального анализа данных (Data Mining)`.
- **Функциональные возможности:** Автоматический ежечасный парсинг открытых данных Единой информационной системы в сфере закупок (ЕИС Закупки, 44-ФЗ и 223-ФЗ). ИИ-модуль с помощью методов обработки естественного языка (NLP) осуществляет семантический анализ ТЗ контрактов, сопоставляет требования заказчиков со свободными ИТ-ресурсами (Scrum-командами) холдинга, прогнозирует чистую маржинальность лота и рассчитывает предиктивную вероятность победы в торгах (Win Rate Probability).

1. **Explainable AI (Модуль «Рассуждений»):** Платформа не выдает «черный ящик». На каждый запрос система генерирует детальное JSON-дерево логических выводов ИИ (`ai_reasoning_tree`), верифицированное по шлюзам СМЭВ 3.0 (ФНС, ФССП, СФР), что полностью закрывает требования ИТ-аудиторов ЦБ РФ и защищает от регуляторных штрафов [ai_scoring_architecture.md, secure_audit.sql].

2. **AVM SOTA-Engine (LSTR-Трансформер):** Модель, обученная на 10-летнем Big Data архиве рынка недвижимости от rpm, выявляет искусственное завышение цен застройщиками с точностью до ≤ 4.5% (по метрике MAPE) и рассчитывает форвардный тренд залога на 3 года вперед (Stress LTV), защищая ваш капитал от деградации [ai_scoring_architecture.md].

3. **Экономия расходов на андеррайтинг:** Интеграция шлюза позволяет сократить штат верификаторов и рисковиков на 70%, снизив себестоимость одной проверки в 4–5 раз по сравнению с классическими методами.

## 7. План развертывания репозитория на серверах Yandex Cloud и настройка GitLab Runner

Инструкция для системных инженеров и DevOps холдинга по развертыванию защищенного контура CI/CD в облаке ГОСТ.

### Шаг 1: Подготовка инфраструктуры в Yandex Cloud

1. Через консоль управления Yandex Cloud создаем закрытую виртуальную сеть (VPC) и приватную подсеть для защищенного контура ИТ-дочки.
2. Создаем виртуальную машину для GitLab Runner в сервисе Yandex Compute Cloud на базе образа Ubuntu 22.04 LTS. Рекомендуемые параметры: 4 vCPU, 8 GB RAM, 50 GB корпоративного SSD.

### Шаг 2: Установка и регистрация GitLab Runner на сервере

Подключаемся к созданной ВМ по SSH и последовательно выполняем команды по установке официального бинарника раннера:

```bash
# 1. Скачивание и установка репозитория GitLab Runner
curl -L "https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh" | sudo bash

# 2. Установка пакета
sudo apt-get install gitlab-runner -y

# 3. Установка Docker (так как раннер будет собирать наш Docker-сценарий)
sudo apt-get install docker.io -y
sudo usermod -aG docker gitlab-runner

Шаг 3: Настройка токенов авторизации (Регистрация в GitLab)

Для того чтобы ваш облачный сервер понимал, из какого именно приватного репозитория ИТ-дочки забирать код скоринга, необходимо связать его через Registration Token:

    Заходим в ваш корпоративный GitLab ➡️ Settings ➡️ CI/CD ➡️ Runners ➡️ Копируем токен авторизации (GR1348948...).

    На сервере Yandex Cloud запускаем интерактивный процесс регистрации:

bash

sudo gitlab-runner register

    Заполняем параметры конфигуратора в консоли:

        Enter the GitLab instance URL: URL вашего гитлаба (например, https://cctech.ru).

        Enter the registration token: Вставляем скопированный токен авторизации.

        Enter a description for the runner: yandex-cloud-fintech-runner-01.

        Enter tags for the runner: fintech-prod, secure-cloud (эти теги должны совпадать с тегами в .gitlab-ci.yml) [.gitlab-ci.yml].

        Enter an executor: docker (раннер будет изолированно запускать сборщик внутри докера).

        Enter the default Docker image: docker:24.0.5 [.gitlab-ci.yml].

Шаг 4: Настройка безопасности и изоляции среды выполнения (config.toml)

Для соответствия ГОСТ Р 57580.1 открываем конфигурационный файл раннера sudo nano /etc/gitlab-runner/config.toml и принудительно включаем работу в защищенном режиме привилегий (отключаем privileged = true для сборщика в целях ИБ):
toml

[[runners]]
  name = "yandex-cloud-fintech-runner-01"
  url = "https://cctech.ru"
  id = 1
  token = "ТОКЕН_АВТОРЫ_РАННЕРА"
  token_obtained_at = 2026-08-23T11:11:00Z
  token_expires_at = 0001-01-01T00:00:00Z
  executor = "docker"
  [runners.custom_build_dir]
  [runners.docker]
    tls_verify = false
    image = "docker:24.0.5"
    privileged = false # ЖЕСТКОЕ ТРЕБОВАНИЕ ЦБ: Отключение privileged-режима Docker-в-Docker
    disable_entrypoint_overwrite = false
    oom_kill_disable = false
    disable_cache = false
    volumes = ["/var/run/docker.sock:/var/run/docker.sock", "/cache"]
    shm_size = 2147483648

Перезапускаем службу для применения ИБ-политик:
bash

sudo systemctl restart gitlab-runner

Шаг 5: Проверка сквозного авто-деплоя

Теперь при каждом коммите в ветку main [.gitlab-ci.yml]:

    GitLab Runner в Yandex Cloud автоматически проснется.

    Скомпилирует наш безопасный Docker-образ скоринга [Dockerfile].

    Прогонит его через сканер Trivy [.gitlab-ci.yml]. Если Trivy найдет хоть одну критическую уязвимость CRITICAL в коде, конвейер мгновенно заблокируется, а наемный СЕО и вы получите алерт [.gitlab-ci.yml, main.py].

    При успехе — образ бесшовно развернется в кластере, а логи Vector начнут литься в ClickHouse для отчетов регуляторам [vector.toml, secure_audit.sql].

8. Рекомендации по развертыванию
Вариант 1: Локальный запуск (для разработки и тестирования)

    Клонируйте репозиторий:
    bash

    git clone https://github.com/Vitaliy951/Ranieri-Core_V2.08.26.git
    cd Ranieri-Core_V2.08.26

    Создайте файл .env на основе .env.example (создайте его самостоятельно).

    Запустите через Docker Compose:
    bash

    docker-compose up -d

    Это поднимет:

        ClickHouse на порту 8123

        FastAPI-сервер на порту 8000

    Проверьте работу:

        API документация: http://localhost:8000/docs

        Dashboard: откройте dashboard.html в браузере

Вариант 2: Развертывание в Yandex Cloud (Production)

    Подготовьте инфраструктуру (согласно инструкции в README):

        Создайте VPC и подсеть.

        Создайте ВМ для GitLab Runner (4 vCPU, 8 GB RAM, 50 GB SSD).

    Настройте GitLab CI/CD:

        Добавьте переменные окружения в GitLab (Settings → CI/CD → Variables):

            YANDEX_CLOUD_OAUTH_TOKEN

            K8S_PROD_SERVER

            K8S_PROD_TOKEN

            K8S_STAGING_SERVER

            K8S_STAGING_TOKEN

    Примените Kubernetes-манифесты:
    bash

    kubectl apply -f k8s/prod/namespace.yaml
    kubectl apply -f k8s/prod/secret.yaml   # предварительно заполнить
    kubectl apply -f k8s/prod/configmap.yaml
    kubectl apply -f k8s/prod/deployment.yaml
    kubectl apply -f k8s/prod/service.yaml
    kubectl apply -f k8s/prod/ingress.yaml

    Настройте ClickHouse внутри кластера или используйте внешний Managed Service for ClickHouse в Yandex Cloud.

    Настройте Ingress и DNS для домена api.ranieri-core.ru.

Вариант 3: Без Kubernetes (для быстрого старта)

Если Kubernetes пока избыточен, можно развернуть на одной ВМ:

    Установите Docker и Docker Compose на ВМ.

    Склонируйте репозиторий и настройте .env.

    Запустите:
    bash

    docker-compose up -d

    Настройте Nginx как reverse proxy для HTTPS.
